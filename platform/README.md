# Платформа лицензирования внешности — MVP-каркас

Рабочий прототип по ТЗ (`../docs/TZ.md`, v1.1, юрисдикция РФ): каталог Talent, регистрация с разделением
биометрического согласия и согласия на конкретную лицензию, заявки → e-signature (упрощённо) → оплата (эскроу как
статусная модель), модерация, споры, аудит-лог обращений к биометрии.

## Что реализовано

- Каталог с фильтрами (пол, жанр, цена), карточка Talent
- Регистрация Talent/Buyer, вход, сессия на httpOnly-cookie (JWT)
- Отдельный экран биометрического согласия + отзыв согласия
- Кабинет Talent: профиль, медиа, заявки на лицензию (одобрить/отклонить)
- Кабинет Buyer: заявки, подписание и оплата, споры, отзывы
- Админ-панель: модерация профилей/медиа, разрешение споров, базовая аналитика
- Аудит-лог всех обращений к биометрическим данным (`AuditLog`)

## Что осознанно оставлено стабом (не входит в объём демо-MVP)

Эти интеграции требуют реальных договоров/API-ключей с провайдерами и не могут быть проверены без них — см.
`docs/TZ.md` разделы 8, 12:

- **KYC/liveness** — при регистрации Talent не вызывается реальный провайдер (VisionLabs/Regula/Multifactor/Госуслуги),
  верификация помечается как `PENDING` без фактической проверки.
- **Платежи** — «оплата» в `signAndPay` создаёт запись `Transaction` со статусом эскроу `HELD`, реального списания
  через ЮKassa/СБП нет.
- **E-signature** — договор подписывается фактом клика в интерфейсе + хешем текста (SHA-256), без интеграции с
  СБИС/Контур.Диадок.
- **Хранение медиа** — `MediaAsset.url` принимает произвольную ссылку вместо реальной загрузки в объектное хранилище
  (Selectel/VK Cloud S3).

Перед production-запуском все четыре пункта требуют реальной интеграции согласно разделу 8 ТЗ, до этого — открытые
юридические и провайдерские решения по разделу 12 ТЗ (юрист по 152-ФЗ, выбор облачного провайдера).

## Запуск локально

```bash
cp .env.example .env      # при необходимости поменяйте SESSION_SECRET
docker compose up -d      # поднимает PostgreSQL
npm install
npm run prisma:migrate    # применяет схему из prisma/schema.prisma
npm run seed               # тестовые данные — см. вывод команды для логинов/пароля
npm run dev                 # http://localhost:3000
```

Тестовые аккаунты после `npm run seed` (пароль для всех — `password123`):

- `admin@platform.ru` — администратор
- `moderator@platform.ru` — модератор
- `buyer@studio.ru` — продюсер/студия
- `anna@talent.ru`, `игорь@talent.ru` и др. — Talent (уже одобрены и опубликованы в каталоге)
