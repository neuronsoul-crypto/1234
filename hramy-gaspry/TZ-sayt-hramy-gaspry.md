Один сайт для двух храмов одного прихода в пгт Гаспра (Ялта, Крым):

|---|---|---|
| Адрес | Алупкинское ш., 46, пгт Гаспра `[TODO: проверить — в открытых источниках встречается и д. 42]` | пгт Гаспра, рядом с храмом Нины `[TODO: точный адрес]` |

## 1. Стек (проверь актуальные версии перед стартом!)

Перед `npm install` выполни `npm view next version` и `npm view payload version` и бери **последние стабильные** (на октябрь 2026 это ветки Next.js 16.x и Payload 3.x). Не используй canary/beta.

- **Next.js** (App Router, TypeScript, Server Components)
- **Payload CMS 3** — встроен в то же Next.js-приложение, админка на `/admin`
- **PostgreSQL** (`@payloadcms/db-postgres`)
- **Tailwind CSS** (последняя стабильная) + CSS-переменные из дизайн-системы (раздел 4)
- **sharp** — обработка изображений; хранение медиа: локально в `/media` на Этапе 1, с возможностью переключить на Yandex Object Storage (S3-адаптер Payload)
- **Шрифты** — self-hosted через `next/font/local` или `next/font/google` (без запросов к Google в рантайме)
- Деплой: VPS в РФ (152-ФЗ — формы собирают персональные данные), Node.js LTS, PM2, nginx, Let's Encrypt. Без Vercel.
- Аналитика: Яндекс.Метрика (ID через env). Карты: Яндекс.Карты (JS API, ключ через env).

`.env.example`: `DATABASE_URL`, `PAYLOAD_SECRET`, `NEXT_PUBLIC_SITE_URL`, `YANDEX_MAPS_KEY`, `YANDEX_METRIKA_ID`, `SMTP_*`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.

## 3. Страницы — содержимое и поведение

### 3.1 Главная `/`
1. **Hero:** полноэкранное фото храма св. Нины (ротация 3–5 фото из CMS), поверх — название и строка «Ближайшая служба: Сб, 18 окт · 17:00 · Всенощное бдение · храм Нерушимая Стена» (живые данные).
2. **Сегодня:** дата по новому и старому стилю, седмица/праздник `[интеграция с церковным календарём — см. 6.3]`.
3. **Расписание на неделю:** компактная таблица, переключатель «Оба храма / Нины / Нерушимая Стена», ссылка `/raspisanie`.
4. **Два храма:** две большие карточки рядом (на мобиле — стопкой), фото + 2 строки + `/подробнее`.
5. **Новости:** 3 последние.
6. **Из архива:** горизонтальная лента 6–8 фото последнего альбома.
7. **Пожертвования:** короткий текст + QR СБП + кнопка.
8. **Как добраться:** карта с двумя метками.

### 3.2 Расписание `/raspisanie` — главная функциональная страница
- Вид по умолчанию: **список по дням** на 2 недели вперёд; переключатель «Неделя / Месяц».
- Фильтр по храму (чипы), выделение праздников (цвет акцента), двунадесятые — отдельная метка.
- У каждой службы: время, название, храм (цветная метка храма), служащий священник (опц.), примечание («исповедь с 8:30»).
- Кнопка «Добавить в календарь» (.ics для одной службы) и подписка на весь календарь (`/raspisanie.ics`, параметр `?hram=`).
- Кнопка «Распечатать» — отдельный print-CSS (A4, чёрно-белый), чтобы вешать на доску объявлений.
- Пустой день не показывать. Прошедшие дни — скрыты, ссылка «Прошедшие службы».

### 3.3 Страница храма `/hramy/[slug]`

## 4. Дизайн-система «Камень и мозаика»

**Идея.** Два храма — две темы, одна система. Храм Нины — светлый крымский известняк и кавказская резьба по камню; «Нерушимая Стена» — византийская мозаика: золото и лазурь (на иконе Богоматерь стоит на золотом фоне, с лазоревыми поручами). Основа — как у Антипы: светлый фон, тёмный текст, много воздуха, один сильный акцент.

### 4.1 Цвета (CSS-токены)

```css
:root {
  /* база */
  --c-bg:        #F6F2EA; /* известняк — основной фон */
  --c-surface:   #FFFDF8; /* карточки */
  --c-ink:       #1C1A17; /* основной текст */
  --c-ink-2:     #5E5850; /* вторичный текст */
  --c-line:      #E2DACB; /* линии, рамки */

  /* акценты */
  --c-gold:      #B08A3E; /* мозаичное золото — главный акцент, праздники */
  --c-gold-soft: #EADBB8;
  --c-lazur:     #1F4E79; /* лазурь — ссылки, кнопки, фокус */
  --c-lazur-ink: #F6F2EA;
  --c-feast:     #8E2A2A; /* киноварь — двунадесятые праздники, только точечно */

  /* метки храмов */
  --c-nina:      #7A8C6E; /* олива/кипарис */
  --c-stena:     #1F4E79; /* лазурь */
}

/* тёмная тема — вечерние службы, AMOLED */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --c-bg: #14130F; --c-surface: #1D1B17; --c-ink: #EFE9DD; --c-ink-2: #A69E90;
    --c-line: #2E2B25; --c-gold: #C9A55C; --c-lazur: #7FA8D1; --c-lazur-ink: #14130F;
  }
}
:root[data-theme="dark"] { /* те же значения, что выше */ }
```
Правило: золото — не больше 10% площади экрана; киноварь — только метки праздников.
Контраст текста ≥ WCAG AA (проверить для `--c-ink-2` на `--c-bg`).

### 4.2 Типографика

| Роль | Шрифт | Где |
|---|---|---|
| Display / заголовки | **Cormorant Garamond** (кириллица, 500–600) | H1–H3, названия храмов, цитаты |
| Текст и интерфейс | **Onest** или **Golos Text** (кириллица, 400/500/600) | всё остальное |
| Церковнославянский (опц.) | **Ponomar Unicode** | цитаты тропарей, если будут |
| Технические «пути» | Onest, 500, `letter-spacing: .02em` | метки `/расписание`, как у Антипы |

Шкала (fluid, `clamp`): `--fs-display: clamp(2.75rem, 6vw, 5.5rem)`, H1 `clamp(2.25rem,4vw,3.5rem)`, H2 `clamp(1.75rem,3vw,2.5rem)`, H3 `1.375rem`, body `1.125rem` (крупнее обычного — аудитория старшего возраста), small `0.9375rem`. Межстрочный: заголовки 1.1, текст 1.6. Длина строки текста ≤ 68 символов.

### 4.3 Сетка и отступы
- 12 колонок, max-width контента 1280px, текстовых лонгридов — 720px.
- Поля: 16px (мобайл), 32px (планшет), 48px (десктоп).
- Шкала отступов: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128.
- Секции главной разделяются отступом 96–128px и тонкой линией `--c-line`, без цветных плашек.

### 4.4 Форма и графика
- Скругления минимальные: 2px (кнопки), 0 (фото). Арочный верх (`border-radius: 999px 999px 0 0`) — **только** для главного фото храма и обложек альбомов: отсылка к аркам.
- Тени не использовать; глубина — через фон `--c-surface` и линии.
- Орнамент: одна тонкая SVG-линия-плетёнка (по мотивам кавказской резьбы) как разделитель — сгенерировать оригинальный, не копировать реальный.
- Иконки: Lucide, stroke 1.5.
- Фото: тёплые, естественный свет, без фильтров; на hero — лёгкое затемнение снизу для текста.

### 4.6 Компоненты (собрать в `/components/ui` + страница-витрина `/styleguide`, закрыта от индексации)
Button (primary лазурь, secondary контур, ghost), PathLabel (`/расписание`), ServiceRow (строка службы), DayGroup, ChurchTag (цветная метка храма), FeastBadge, NewsCard, AlbumCard, Lightbox, ChurchCard (арочное фото), Timeline (история), DonateBlock (QR + реквизиты), FormField, Toast, MapBlock, Breadcrumbs, Pagination, ThemeToggle, FontSizeToggle (A / A+ / A++).

## 6. Ключевые функции

### 6.1 Удобный ввод расписания (критично — это будут делать каждую неделю)
1. Кнопка «Сгенерировать неделю из шаблона» → создаёт черновики `services` по `scheduleTemplates`, дальше правка вручную.
2. **Импорт из текста:** поле в админке, куда вставляется расписание в свободном виде, например:
   ```
   18 окт, сб — 17:00 Всенощное бдение (Нерушимая Стена)
   19 окт, вс — 9:00 Божественная литургия (Нины)
   ```
   Парсер разбирает дату, время, название, храм → показывает предпросмотр → сохранить. Нераспознанные строки подсвечивать.
3. Дублирование службы, массовое удаление, календарный вид в админке.

### 6.2 Telegram
При публикации новости с `sendToTelegram = true` — пост в канал прихода (заголовок, лид, обложка, ссылка). Заявки `requests` — уведомление в служебный чат. Расписание на неделю — команда `/raspisanie` у бота (Этап 3).

### 6.3 Церковный календарь
Блок «Сегодня» (дата нов./ст. стиль, память святых, пост/сплошная седмица). Вариант 1 — подключить виджет/API православного календаря (проверь, что доступно и разрешено условиями сайта-источника, напр. azbyka.ru); вариант 2 — ручное поле в `settings`. Не парсить чужие сайты без разрешения.

### 6.4 Доступность для старшего поколения
Переключатель размера шрифта (сохраняется в localStorage с try/catch), контраст AA, весь функционал с клавиатуры, крупные зоны нажатия (≥ 44px), alt у всех фото, понятные формулировки без жаргона.

## 6А. Админ-панель (`/admin`) — обязательная часть проекта

Сайт целиком управляется из админки без программиста. Работать в ней будут настоятель, староста или волонтёр. Это не технические люди, часто они заходят с телефона. Главный критерий: **человек без подготовки разбирается за 10 минут по инструкции.**

### 6А.1 Основа
- Payload CMS 3 Admin, встроенный в проект, адрес `/admin` (можно сменить через env, напр. `/upravlenie`).
- Интерфейс полностью на русском: локализация Payload `ru` плюс русские подписи всех коллекций, полей, кнопок и подсказок (`admin.description` у каждого неочевидного поля).
- Брендинг админки в стилистике сайта: логотип, цвета `--c-lazur` и `--c-gold`, шрифт Onest (кастомные `graphics.Logo/Icon` и CSS).
- **Адаптив:** все сценарии из 6А.3 проверены на ширине 375px.

### 6А.3 Сценарии, которые должны работать идеально

### 6А.4 Удобства редактора
- **Черновики и предпросмотр** (Payload Drafts + Live Preview): видно, как будет выглядеть на сайте, до публикации.
- **Отложенная публикация** новостей и объявлений по дате и времени.
- **История версий** с откатом для новостей, страниц и настроек.
- **Автосохранение** черновиков.
- Rich text (Lexical) с ограниченным набором: заголовки H2–H3, жирный, курсив, ссылка, цитата, список, фото, галерея, видео (VK/Rutube embed). Без выбора цветов и шрифтов, чтобы сайт не «разъехался».
- Обязательный `alt` у фото с подсказкой «опишите, что на фото»; при пустом поле подставлять подпись.
- Фокус-точка (focal point) у изображений, чтобы обложки не обрезали купол.
- Поиск по всем коллекциям, фильтры по храму и дате.
- Справочник названий служб, чтобы не вбивать «Божественная литургия» каждый раз.

### 6А.5 Пользователи и безопасность
- Роли (см. раздел 5): `admin`, `editor`, `clergy`. Права на уровне коллекций и полей; `requests` с ПДн видят только `admin` и `clergy`.
- Добавление пользователя по приглашению на e-mail, сброс пароля по почте.
- Пароль от 10 символов; блокировка после 5 неудачных попыток на 15 минут; сессия 7 дней.
- Двухфакторная аутентификация (TOTP) — опционально для `admin`.
- Журнал действий: кто создал, изменил или удалил запись.
- Удаление через корзину (soft delete, 30 дней), кроме медиа, используемых в материалах (запрет удаления с предупреждением).
- Админка закрыта от индексации (`noindex`, `robots.txt`).

### 6А.6 Уведомления
- Новая заявка → e-mail и Telegram ответственному (настраивается в «Настройках»).
- Понедельник, 10:00 → напоминание в Telegram «Расписание на следующую неделю не заполнено», если служб нет.

### 6А.7 Инструкция
`docs/instrukciya-redaktora.md` плюс PDF: по одному разделу на каждый сценарий из 6А.3, со скриншотами, простым языком. Дополнительно короткая шпаргалка на 1 страницу A4 для печати.

### 6А.8 Критерии приёмки админки
- Человек, не видевший админку, по инструкции вносит неделю служб, публикует новость с 10 фото и закрывает заявку, без вопросов к разработчику.
- Все сценарии 6А.3 выполнимы с телефона.
- Пользователь с ролью `editor` не видит заявки и не может менять настройки и пользователей.

## 7. SEO и техника
- Метаданные и OG-картинки для всех страниц (OG генерировать динамически в стиле дизайн-системы).
- schema.org: `Church` (оба храма, с адресом и гео), `Event` для служб на 2 недели вперёд, `NewsArticle`, `BreadcrumbList`.
- `sitemap.xml`, `robots.txt`, канонические URL, транслит-slug.
- Регистрация в Яндекс.Вебмастере и Яндекс.Бизнесе — ссылки на сайт с карточек обоих храмов `[делает заказчик]`.
- Производительность: Lighthouse ≥ 90 по всем пунктам на мобиле, LCP < 2.5 с, изображения ≤ 200 КБ на экране.
- Кэширование: расписание и новости — revalidate при сохранении в CMS (on-demand revalidation).
- 152-ФЗ: согласие на обработку ПДн в каждой форме (чекбокс, не отмечен по умолчанию), политика ПДн, cookie-баннер для Метрики, данные хранятся на сервере в РФ.
- Защита форм: honeypot + rate-limit; без reCAPTCHA (Google). Опционально Yandex SmartCaptcha.
- Бэкап БД и `/media` раз в сутки (cron + pg_dump), хранить 14 копий.

## 8. Этапы работ

**Этап 1 — каркас и дизайн-система**
Инициализация проекта, Payload + Postgres, токены и шрифты, все UI-компоненты, `/styleguide`, шапка/подвал/меню, тёмная тема, размер шрифта.
*Готово, когда:* `/styleguide` показывает все компоненты в обеих темах, `npm run build` без ошибок и предупреждений TS.

**Этап 2 — контент и страницы**
Коллекции из раздела 5, все страницы из раздела 2, наполнение демо-данными (2 храма, 3 недели расписания, 6 новостей, 4 альбома с плейсхолдерами), SEO, sitemap.
*Готово, когда:* все маршруты открываются, расписание фильтруется и печатается, .ics открывается в Google/Apple Календаре, Lighthouse ≥ 90.

**Этап 3 — функции и админка**
Кастомный дашборд и брендинг админки (6А), роли и безопасность, черновики, предпросмотр, версии, шаблоны недели и текстовый импорт расписания, формы (записки, таинства) → CMS + e-mail + Telegram, автопостинг новостей, блок «Сегодня».
*Готово, когда:* редактор без помощи разработчика вносит неделю служб за ≤ 5 минут.

**Этап 4 — запуск**
Деплой на VPS (nginx, PM2, HTTPS), бэкапы, Метрика, инструкция для редактора `docs/instrukciya-redaktora.md` (с картинками, простым языком), передача доступов.
