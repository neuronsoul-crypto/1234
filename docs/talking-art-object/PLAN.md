# Говорящий арт-объект: план реализации

Основа: концепция «ART / VOICE. Говорящий арт-объект» от 15.09.2026.
Задача: зеркальная скульптура разговаривает с посетителями голосом, рассказывает о себе, об авторе и о парке и держит заданный образ.

---

## 1. Что строим (MVP)

**Режим:** один посетитель или одна группа, кнопка «Задать вопрос» (push-to-talk). Кнопка на улице надёжнее постоянного прослушивания: музыка, прохожие и соседние разговоры не запускают объект.

**Сценарий:**

```
[IDLE] --датчик присутствия--> [GREETING] приветствие + подсветка
   ^                                 |
   |                           кнопка нажата
   |                                 v
   |                          [LISTENING] свет «слушаю», запись до отпускания кнопки / паузы (VAD)
   |                                 v
   |                          [THINKING]  свет «думаю»: STT -> LLM
   |                                 v
   |                          [SPEAKING]  свет «говорю»: TTS -> динамик
   |                                 v
   +--нет присутствия N сек--- [DIALOG]  ждём уточнения; память беседы жива
         (сброс памяти)
```

**Критерии готовности MVP:**
- от окончания вопроса до первого звука ответа не больше 2,5 с (p90);
- ответ длится 10–25 с, 1–4 предложения, персонаж не выходит из образа;
- без интернета объект произносит заранее записанные реплики и не зависает;
- после перезагрузки или сбоя объект сам возвращается в работу меньше чем за 60 с;
- расход на ИИ-сервисы не выходит за дневной лимит.

## 2. Архитектура

```
┌─────────────────────────── Мини-ПК (Ubuntu 24.04 LTS) ───────────────────────────┐
│                                                                                   │
│  voice-core (Python 3.12, asyncio)                                                │
│   ├─ StateMachine        IDLE/GREETING/LISTENING/THINKING/SPEAKING/DIALOG         │
│   ├─ AudioIn             PortAudio, 16 кГц моно, VAD (Silero), шумоподавление     │
│   ├─ STT provider  ──►   Yandex SpeechKit (потоковое распознавание, API v3)       │
│   ├─ Brain               промпт персонажа + база знаний + память беседы + фильтры │
│   │    └─ LLM provider ► YandexGPT (AI Studio) | GigaChat | OpenAI*               │
│   ├─ TTS provider  ──►   Yandex SpeechKit (синтез, потоковая отдача по фразам)    │
│   ├─ AudioOut            воспроизведение, громкость по расписанию                 │
│   ├─ Fallback            WAV-реплики на случай офлайна или ошибок                 │
│   └─ HardwareLink ◄──►   USB-Serial (JSON) к контроллеру                          │
│                                                                                   │
│  admin-panel (FastAPI + простой веб-интерфейс, доступ через VPN/Tailscale)        │
│  SQLite: настройки, журнал диалогов (текст), расходы                              │
│  systemd + watchdog, логирование, оповещения в Telegram                           │
└───────────────────────────────────────────────────────────────────────────────────┘
            │ USB
┌───────────▼──────────────┐
│ ESP32 (контроллер)        │  кнопка с подсветкой, датчик присутствия (mmWave LD2410),
│ прошивка Arduino/PlatformIO│  адресная LED-лента (WS2812) — состояния «слушаю/думаю/говорю»
└──────────────────────────┘
```

\* OpenAI Realtime API как альтернатива, если для площадки доступны сервис и оплата. Для Крыма и РФ по умолчанию берём Yandex (и GigaChat как запасной LLM). Провайдеры спрятаны за интерфейсами, поэтому замена сводится к правке конфигурации.

### Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Конвейер | STT → LLM → TTS (каскад) | Каждый шаг контролируется, есть выбор провайдеров, дешевле Realtime, доступно в РФ |
| Задержка | Потоковое распознавание, стриминг токенов LLM, синтез по первому предложению | Первый звук через ~1,5–2,5 с вместо 4–6 с |
| Эхо | В MVP полудуплекс: пока объект говорит, микрофон закрыт | Эхоподавление нужно только для перебиваний (этап 2) |
| Кнопка/свет | Отдельный ESP32 | Мини-ПК без GPIO; контроллер держит свет, даже когда ПК перегружается |
| Датчик присутствия | mmWave (LD2410), а не PIR | PIR на улице ловит солнце и нагрев металла |
| База знаний | Целиком в системном промпте (если меньше ~15–20 страниц) | RAG на старте не нужен; позже можно добавить поиск по фрагментам |
| Хранение | Только текст диалогов, аудио не пишем | Меньше рисков по 152-ФЗ; табличка «объект слушает, только по кнопке» |

## 3. Программная часть: структура репозитория

```
talking-art/
├─ voice_core/
│  ├─ main.py               # запуск, сборка зависимостей
│  ├─ state_machine.py      # состояния и переходы, таймауты
│  ├─ audio/{input,output,vad}.py
│  ├─ providers/
│  │  ├─ stt/{base,yandex}.py
│  │  ├─ llm/{base,yandexgpt,gigachat,openai}.py
│  │  └─ tts/{base,yandex}.py
│  ├─ brain/
│  │  ├─ persona.py         # сборка системного промпта
│  │  ├─ session.py         # память беседы, сброс
│  │  └─ guardrails.py      # запретные темы, длина, фильтр мата, отказ «в образе»
│  ├─ hardware/serial_link.py
│  ├─ fallback.py
│  └─ budget.py             # счётчик расходов, дневной лимит
├─ admin/                   # FastAPI + шаблоны/HTMX
├─ firmware/esp32/          # PlatformIO: кнопка, датчик, LED
├─ content/
│  ├─ persona.yaml          # имя, характер, манера речи, примеры ответов
│  ├─ knowledge.md          # об объекте, авторе, парке
│  └─ fallback/*.wav        # офлайн-реплики
├─ deploy/                  # systemd-юниты, install.sh, конфиг ALSA/PipeWire
├─ tests/                   # юнит-тесты + прогон сценариев без звука
└─ config.example.yaml
```

### Модули и требования

1. **State machine.** Явные состояния, таймауты (приветствие не чаще раза в 60 с, сброс беседы через 30–45 с без присутствия, максимум 15 с записи), обработка ошибок на каждом шаге с переходом в fallback.
2. **Audio.** Запись 16 кГц, моно. VAD обрезает тишину и завершает запись, если кнопку держат дольше, чем говорят. Автоматическая регулировка громкости по расписанию (днём громче, вечером тише).
3. **STT.** Потоковый gRPC SpeechKit v3, язык ru-RU, подсказки со словами-терминами (имя автора, названия парка) для лучшего распознавания.
4. **Brain.**
   - Промпт персонажа: имя, характер, манера речи, правила («отвечай 1–4 предложениями», «не выходи из образа», «на провокации отвечай шуткой и возвращай разговор к искусству»).
   - Память: последние 6–10 реплик текущей беседы.
   - Guardrails: список запретных тем (политика, религия, медицина, 18+), фильтр входа и выхода, отказ формулируется в образе.
   - Стриминг ответа по предложениям в TTS.
5. **TTS.** SpeechKit: выбрать голос и роль под характер, тонкая настройка скорости и интонации. Кэш частых фраз (приветствия, отказы) в WAV.
6. **Fallback.** Нет сети, таймаут провайдера или лимит исчерпан: объект проигрывает случайную из заготовленных реплик («Я задумался… спроси меня чуть позже»).
7. **Budget.** Учёт секунд STT, символов TTS и токенов LLM; дневной и месячный лимит; при превышении объект переходит в офлайн-режим, администратору уходит оповещение.
8. **Admin-панель.** Настройки голоса, громкости и расписания работы; редактор персонажа и базы знаний с кнопкой «проверить ответ» (текстовый чат); журнал диалогов; расходы; статус (сеть, микрофон, контроллер); перезапуск.
9. **Надёжность.** systemd `Restart=always` и watchdog, аппаратный watchdog на ESP32 (если ПК молчит, свет гаснет или включается режим «сплю»), автозапуск после отключения питания (настройка BIOS), health-check и оповещения в Telegram, ротация логов.

### Прошивка ESP32
- Отправляет события: `button_down`, `button_up`, `presence_on`, `presence_off`.
- Принимает команды: `led_state {idle|greet|listen|think|speak|error|sleep}`, `led_brightness`.
- Встроенные анимации: дыхание в idle, пульс при прослушивании, «бегущая волна» во время раздумья, свет в такт речи (по уровню, который присылает ПК).
- Антидребезг кнопки, heartbeat раз в секунду.

## 4. Аппаратная часть (для теста на площадке)

| Узел | Ориентир для MVP | Что проверить на месте |
|---|---|---|
| Мини-ПК | Intel N100/N305, 16 ГБ RAM, SSD 256 ГБ, промышленный или безвентиляторный корпус | Нагрев в шкафу на солнце |
| Микрофон | Направленный (суперкардиоида/гиперкардиоида) с ветрозащитой на стойке у кнопки, либо USB-массив с DSP (ReSpeaker и аналоги) | Шум, ветер, дистанция до рта 30–60 см |
| Аудиоинтерфейс | USB-интерфейс с фантомным питанием, если микрофон XLR | Шумы, земляные петли |
| Динамик + усилитель | Уличный всепогодный динамик (IP65+), усилитель класса D | Разборчивость, зона слышимости, дребезг конструкции |
| Кнопка | Антивандальная с подсветкой, IP67 | Нажатие мокрыми руками, яркость на солнце |
| Датчик присутствия | mmWave LD2410 (опционально) | Ложные срабатывания от прохожих |
| Подсветка | Адресная лента + ESP32 | Видимость днём |
| Связь | Кабель или LTE-роутер с внешней антенной | Задержка (ping) и стабильность в пиковые часы |
| Шкаф | IP54+, вентиляция с фильтром, подогрев/осушение от конденсата | Температура внутри днём |
| Питание | ИБП на 10–15 мин, УЗО, заземление конструкции (**делает электрик**) | Скачки напряжения |

Интеграция в металлическую конструкцию:
- динамику нужен акустический выход (перфорация или решётка), сплошной металл глушит звук;
- виброизоляция крепления, иначе дребезг;
- микрофон и динамик разнести как можно дальше;
- защита от солёного воздуха: нержавеющий крепёж, конформное покрытие плат, герметичные разъёмы.

## 5. Этапы и сроки

| # | Этап | Длительность | Результат (что принимаем) |
|---|---|---|---|
| 0 | **Исходные данные** | 3–5 дней | Место и город, питание, интернет, чертежи скульптуры, круг тем, характер персонажа, тексты об авторе и парке |
| 1 | **Прототип на ноутбуке** | 1–2 недели | Каркас voice-core, провайдеры Yandex, персонаж, клавиша пробел вместо кнопки. Демо заказчику: голос, характер, качество ответов. Утверждаем голос и персонажа |
| 2 | **Стенд с «железом»** | 1–2 недели | Мини-ПК, микрофон, динамик, ESP32 с кнопкой, светом и датчиком. Fallback, лимиты, автозапуск. Прогон 24 часа без сбоев |
| 3 | **Тест у объекта** | 2–3 дня | Замеры ветра, шума, эха, связи, нагрева. Фиксируем комплект оборудования и точки монтажа |
| 4 | **Доводка и админ-панель** | 1–2 недели | Панель, журнал, расходы, оповещения, эхоподавление (если нужно), тонкая настройка guardrails по реальным вопросам |
| 5 | **Монтаж и запуск** | 2–3 дня | Установка, настройка акустики, приёмочная проверка на площадке, инструкция для персонала |
| 6 | **Пилот** | 2 недели | Разбор журналов, донастройка промпта и знаний, решение по перебиваниям и режиму без кнопки |

Итого до запуска: около 5–8 недель. Этапы 1 и 2 частично идут параллельно с закупкой оборудования.

### Этап 1: разбивка задач
1. Каркас проекта, конфиг, логирование.
2. Запись с микрофона ноутбука + VAD.
3. Провайдер STT (SpeechKit v3 streaming).
4. Провайдер LLM (YandexGPT) со стримингом; промпт персонажа из `persona.yaml` и `knowledge.md`.
5. Провайдер TTS со стримингом по предложениям.
6. State machine с клавиатурой вместо кнопки.
7. Замер задержек по этапам, выводим в лог.
8. Набор из 50 тестовых вопросов (обычные, каверзные, провокационные) с автоматическим прогоном текстом и ручной оценкой.

## 6. Стоимость (статьи, без цифр до выбора моделей)

- **Оборудование:** мини-ПК, аудиотракт, кнопка и ESP32, свет, шкаф, ИБП, роутер.
- **Монтаж:** электрик, металлоработы (акустическое окно, крепления), настройка звука.
- **Эксплуатация в месяц:** интернет; SpeechKit (оплата за секунды распознавания и символы синтеза); LLM (оплата за токены). Точная сумма считается по ожидаемому числу диалогов в день после этапа 1: в прототипе замеряем фактический расход на один диалог.
- **Разработка:** софт, панель, прошивку и инструкции можно сделать с помощью ИИ-ассистента; физический монтаж и финальная настройка звука выполняются на месте.

## 7. Риски и как их снимаем

| Риск | Мера |
|---|---|
| Ветер и шум мешают распознаванию | Кнопка + направленный микрофон с ветрозащитой + VAD; проверка на этапе 3 |
| Плохая связь | LTE с внешней антенной, офлайн-реплики, мониторинг ping |
| Долгий ответ, посетитель уходит | Стриминг на всех этапах, короткие ответы, звуковой или световой «задумался» |
| Провокации, неуместные ответы | Guardrails, запретные темы, журнал и еженедельный разбор на пилоте |
| Недоступность сервиса или оплаты в регионе | Абстракция провайдеров, запасной LLM (GigaChat) |
| Перегрев, конденсат, соль | Шкаф с вентиляцией и осушением, безвентиляторный ПК, защита плат |
| Вандализм | Антивандальная кнопка, микрофон и динамик за решёткой, скрытый шкаф |
| Перерасход бюджета | Дневной лимит, автоматический офлайн-режим, оповещение |
| Персональные данные | Аудио не сохраняется, в журнале только текст без идентификаторов, информационная табличка |

## 8. Что нужно от заказчика для старта

1. Место и город установки, фото и чертежи скульптуры (внутренние полости, сервисный доступ).
2. Наличие питания (220 В, мощность) и интернета на точке.
3. Круг тем: только объект и парк или свободное общение.
4. Персонаж: имя, характер, возраст «голоса», манера речи, примеры желаемых ответов.
5. Тексты: об объекте, авторе и парке, частые вопросы посетителей.
6. Часы работы объекта и требования к громкости.
7. Кто оплачивает облачные сервисы (юрлицо для Yandex Cloud) и допустимый месячный бюджет.

## 9. Дальнейшее развитие (после пилота)

- Перебивание объекта голосом (full duplex, аппаратное эхоподавление).
- Режим без кнопки по ключевому слову («Привет, …»).
- Несколько языков (en, zh) с автоопределением.
- Офлайн-режим: локальные STT/LLM/TTS (Whisper + локальная LLM + Silero TTS), нужен ПК с GPU и отдельная проверка скорости и качества.
- Статистика: популярные вопросы, пиковые часы, средняя длина беседы.
