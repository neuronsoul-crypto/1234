# ТЗ для Claude Design: дорожная карта проекта

**Проект:** платформа лицензирования внешности для ИИ-контента (докс `docs/TZ.md` v1.1)
**Задача:** визуальная дорожная карта (roadmap) — один канвас/инфографика, которую можно показать команде
и партнёрам, чтобы было видно, что уже сделано, что делается сейчас и что впереди.

---

## 1. Формат

- Один артборд, альбомная ориентация (широкий таймлайн), не слайд-дек.
- Горизонтальная временная шкала слева направо: **MVP → Этап 2 → Этап 3**.
- Три параллельные дорожки (swimlanes) на каждом этапе — по ним и группируется контент:
  1. **Продукт / функционал**
  2. **Юридический трек / комплаенс**
  3. **Инфраструктура / деплой**
- Явный маркер «мы здесь» — между MVP и Этапом 2 (см. раздел 3, «Текущий статус»).
- Между этапами — точки-гейты (ромб/флажок), подписанные открытым вопросом, который нужно закрыть
  до перехода дальше (раздел 4).

## 2. Тон и стиль

- Деловой, спокойный, без маркетингового пафоса — это внутренний/партнёрский документ, не рекламный.
- Держать цветовую и шрифтовую схему согласованной с уже переданной презентацией проекта
  (`Презентация_проекта.docx`) — тот же продукт, тот же визуальный язык.
- Юридический трек можно выделить отдельным акцентным цветом (например, отличным от продуктового) —
  это единственный трек, который прямо влияет на то, можно ли вообще запускаться (раздел 6 ТЗ).

## 3. Текущий статус (маркер «мы здесь»)

На момент составления карты:

- Код MVP-каркаса собран и работает (Next.js + PostgreSQL): каталог, регистрация, биометрическое
  согласие, кабинеты Talent/Buyer, админ-панель, аудит-лог. Полный цикл лицензии (заявка → одобрение →
  оплата → активная лицензия) проверен вручную.
- Идёт первый деплой демо-версии на сервер (tavrida-osmotr.ru/aifaces) — для показа, не для реальных
  пользователей.
- Юридический трек не начат: юрист по 152-ФЗ ещё не привлечён, оферта и тексты согласий — черновые.
- Реальные интеграции (KYC/liveness, платежи, e-signature, хранение медиа в объектном хранилище) —
  осознанные заглушки, не подключены.

Это положение маркера «мы здесь» — на границе MVP, ближе к его концу по продукту, но в самом начале
по юридическому треку. Это стоит показать на карте явно (два трека не синхронны).

## 4. Контент по этапам

### MVP (месяц 1–2 от старта разработки)

**Продукт:**
- Регистрация Talent/Buyer, KYC + liveness-check (обязательно, не отложено)
- Каталог с фильтрами, загрузка фото, анкета типажа
- Заявка на лицензию → согласие → e-signature → оплата (без полноценного эскроу)
- Базовая админ-панель для модерации

**Юридический трек:**
- Отдельное биометрическое согласие (ст. 11 152-ФЗ)
- Оферта с разграничением: лицензирование изображения ≠ биометрическая идентификация
- Юридическая консультация по 152-ФЗ и ст. 152.1 ГК РФ — **гейт, блокирует публичный запуск**

**Инфраструктура:**
- Хостинг только в РФ (152-ФЗ, локализация данных)
- Изолированное хранилище биометрии без публичного доступа
- Аудит-лог обращений к биометрии

**Гейт перед Этапом 2:** выбор облачного провайдера (Selectel / VK Cloud / Timeweb Cloud / Cloud.ru)
после оценки реальной нагрузки первых месяцев; решение — эскроу с первого дня или ручной арбитраж.

### Этап 2 (месяц 3–4)

**Продукт:**
- Полноценная эскроу-логика, автоматизация выплат, налоговые документы (НПД)
- Фасетный/полнотекстовый поиск (Meilisearch)
- Модуль разрешения споров
- Водяные знаки и трекинг материалов

**Юридический трек:**
- Финальные тексты оферты и согласий после консультации юриста
- Регистрация оператора персональных данных в реестре Роскомнадзора

**Инфраструктура:**
- Реальные интеграции: KYC-провайдер, ЮKassa/СБП, e-signature (СБИС/Диадок)
- Переход с демо-хостинга на боевую инфраструктуру по разделу 8.1 ТЗ

**Гейт перед Этапом 3:** допускать ли агентства (управление несколькими профилями) — решение отложено
с MVP, принять по факту роста базы Talent.

### Этап 3 (месяц 5–6+)

**Продукт:**
- API-интеграция с инструментами ИИ-генерации
- Автоматический мониторинг неправомерного использования в сети
- Агентский функционал в полном объёме
- Рекомендательная система подбора

**Юридический трек:**
- Регулярный аудит соответствия по факту роста объёма данных

**Инфраструктура:**
- Горизонтальное масштабирование, отдельный поисковый кластер
- KMS/HSM для ключей шифрования биометрии

## 5. Элементы, которые должны быть легко редактируемыми

Даты и длительности этапов — условные плейсхолдеры («месяц 1–2» и т.д.), реальных сроков заказчик
ещё не утверждал. В канвасе эти подписи должны быть отдельными текстовыми блоками, которые можно
быстро поправить, не перестраивая всю структуру.

## 6. Источник контента

Весь фактический материал — из `docs/TZ.md` (v1.1): раздел 10 (этапность), раздел 12 (открытые
решения), раздел 6 (юридический блок), раздел 8.1 (инфраструктура). При расхождении между этим брифом
и `docs/TZ.md` — приоритет у `docs/TZ.md`, этот файл лишь раскладывает его содержание под визуал.
